# Диаграммы (PlantUML)

Диаграмма — артефакт **для человека**: проверить логику глазами, обсудить с командой, спроектировать пользовательский flow. Обязательный контекст агентов остаётся текстовым, поэтому диаграммы живут в отдельных файлах, а `_spec.md`, `_task_plan.md`, `docs/<slug>.md` получают только **раздел «Диаграммы» со ссылками** на них.

## Главное правило

**Диаграмма дублирует текст, а не заменяет его.** Требование, которого нет в исходном файле, не может появиться на диаграмме: иначе оно начнёт жить только в картинке, и ни `spec_check`, ни генерация кода его не увидят. Нашли на исходнике пробел — сообщить пользователю, а не дорисовывать.

## Тип под цель

| Цель | Тип | Когда применять |
| ---- | --- | --------------- |
| Алгоритм, бизнес-процесс, ветвления сценария | Activity | UC с 3+ альтернативными потоками; процесс согласования |
| Функциональность с точки зрения актора | Use Case | 2+ UC с разными действующими лицами; `<<include>>` / `<<extend>>` |
| Структура данных и связи | Class / Object | 3+ таблиц или 2+ Reference-связи: кардинальность, зависимые поля |
| Жизненный цикл записи | State | Есть статусная модель и переходы: кто из какого статуса куда, тупиковые статусы |
| Обмен с внешними системами | Sequence | Интеграции, вызовы REST, асинхронные обработчики |

Одна диаграмма — одна мысль. Не смешивать модель данных и процесс в одном файле.

## Оформление

- Каждая диаграмма — отдельный `.puml` + одноимённый `.svg`: **одно имя на оба файла**.
- Имя файла: `<имя исходного файла>-<slug-диаграммы>.puml` (`_spec-use-cases.puml`, `_spec-state-model.puml`).
- Первая строка после `@startuml` — подключение общей темы относительным путём до `<product>/docs/theme.puml`:

  ```plantuml
  @startuml use-cases
  !include ../../docs/theme.puml
  ```

  Из `<product>/tasks/<task_id>/` это `../../docs/theme.puml`, из `<product>/docs/` — `theme.puml`. Путь считается от расположения `.puml`; темы нет на месте — `!include` не добавлять и сказать об этом пользователю.
- Обязательный `title` на русском.
- Подписи — на языке исходного файла (русский), системные имена таблиц/колонок — в обратных кавычках или как есть латиницей.
- В markdown-файле — картинка, сразу за ней ссылка на код:

  ```markdown
  ![Сценарии использования](_spec-use-cases.svg)

  [Ссылка на код диаграммы](_spec-use-cases.puml)
  ```

## Чего не делать

- Не рисовать диаграмму ради диаграммы: 1 таблица без связей, UC из трёх линейных шагов — текст читается лучше.
- Не хранить в диаграмме то, чего нет в тексте (см. главное правило).
- Не встраивать PlantUML-код и картинки в `_spec.md` / `_task_plan.md` / `docs/<slug>.md` — в исходнике только раздел «Диаграммы» со ссылками на `.svg` / `.puml`.
- Не отправлять содержимое спецификаций на публичные рендер-серверы (`plantuml.com`, публичный Kroki) — только локальный рендер или внутренний сервер компании.
