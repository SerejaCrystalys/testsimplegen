# Интерфейсные тексты (RU/EN)

## Общие правила

- Тексты на `ru` и `en` одновременно; английский — американский (`en-US`).
- Ясно, кратко, только необходимое. **Ключевая информация — в начале** предложения/сообщения.
- Аббревиатуры и устоявшиеся выражения не искажать (`ID`, `CSS`, `HTML`).
- Технику, коды ошибок, выдержки логов — только для администраторов; обычным пользователям — без техники, при необходимости дать контакт поддержки.
- Не возлагать вину на пользователя; избегать отрицаний (вместо «нельзя…» — что можно сделать).
- Кавычки прямые `" "` (не `« »`); в EN кавычки — только при крайней необходимости. В RU — «е» вместо «ё». Не начинать с «Пожалуйста / Please».
- **Смысловая локализация**: перевод передаёт смысл, не калькирует структуру. RU и EN могут различаться по грамматике/порядку/числу слов. Не калькировать при наличии устоявшегося эквивалента (`Configure`→`Настройки` не «Сконфигурируйте»; `In Progress`→`В работе`; `Assignment Group`→`Группа назначения`). При сомнениях — существующие переводы в `domain/localization/`.

## Капитализация и число по типам

EN: `Title Case` — заголовки таблиц, секций, связанных списков, категории/пункты меню навигатора, заголовки диалоговых/модальных окон. `Sentence case` — заголовки полей, опции выбора, сообщения, UI Actions, контекстное/бургер-меню. RU: всегда `Sentence case` (заглавная только первое слово).

| Сущность | RU | EN | Число / специфика |
|---|---|---|---|
| Таблица (`sys_db_table`) | мн.ч., ≤3 слов | Title Case, ед.ч. | `name` = EN-заголовок в snake_case (`User Query`→`user_query`); «сборник»/log — семантическое исключение |
| M2M (`sys_m2m`) | мн.ч. | Title Case, мн.ч. | семантика связи/состава, не действия |
| Колонка (`sys_db_column`) | Sentence, ед.ч., ≤3 слов | Sentence, ед.ч. | List → мн.ч. + суффикс `_ids`; Reference → суффикс `_id`; `name` = EN-заголовок snake_case; boolean/toggle — заголовок = результат включения |
| Секция формы | Sentence | Title Case | существительное/словосочетание, без глаголов; объясняет содержание |
| Категория меню | Sentence | Title Case | существительное-раздел, обобщает пункты; не `Разное/Other`; устоявшиеся аббревиатуры (REM, ACL) как есть |
| Пункт меню | Sentence | Title Case | ведёт на список → имя таблицы/сущности, мн.ч. (`Все инциденты`/`All Incidents`) |
| Связанный список | мн.ч. | мн.ч. | из имени таблицы; отразить преднастроенные фильтры в заголовке |
| Динамич. связ. список | — | — | содержит сущность + логику формирования |
| Опция выбора (`sys_choice`) | Sentence | Sentence | короткая фраза состояния/типа, без точки, единая грамформа в наборе |
| UI Action | Sentence | Sentence | кнопка — глагол (RU императив / EN base verb); пункт меню списка — сущность мн.ч.; ссылка — краткое действие |
| Динамич. ссыл. ограничитель | Sentence | Sentence | контекст применения (роль/таблица) + что ограничивает |

Согласованность: один объект/процесс/действие называть одинаково во всей системе. Пункты, ведущие на списки (бизнес-правил/скриптов/элементов), — во мн.ч.

Плейсхолдеры: единый синтаксис `{placeholder}`. В RU имена сущностей в кавычках, в EN — без.

## Подсказки полей (`sys_field_info`)

| Тип | Правила |
|---|---|
| Справка (Help) | 1–2 предложения, объясняет неочевидную механику; точка в конце; **без** названия поля; без ссылок на изменяемые сущности/опции |
| Placeholder | призыв к действию или пример значения; кратко, обычно без точки |
| Tooltip (hover) | 1 фраза / 1 короткое предложение; точка если это описание; без названия поля |
| Validation hint | «что не так» + «что сделать»; точка; ≤1 строки; без названия поля |

Примеры: Help — `Партнёр может развивать выявленную возможность сам или совместно с вендором.`; Placeholder — `Введите наименование фильтра` / `Enter the filter name`; Validation — `Код проекта должен содержать от 2 до 8 латинских букв или цифр.` / `The project code must contain 2–8 latin letters or numbers.`

## Сообщения

- **Всплывающие (toast)**: Sentence case; плейсхолдеры `{id}`/`{name}`; точку ставить только если 2+ предложений; есть решение — добавить краткие шаги; без техники/кодов для обычных пользователей; при необходимости — ссылка на список затронутых записей. Пример: `Фильтр сохранён` / `The filter is saved`; `Фильтр с такими условиями уже существует` / `A filter with these conditions already exists`.
- **Под полем (validation)**: «что не так» + «что сделать»; точка; без названия поля. Пример: `Дата начала не может быть раньше текущей.` / `The start date cannot be earlier than the current date.`
- Не: вина пользователя, коды ошибок пользователю, ключевая информация в конце, «Недопустимое значение» без подсказки.

## Скрипты (`sys_script*`, includes, scheduled, notification, re_model_client_script)

Названия и описания — **по умолчанию на английском**, `Sentence case` (другой язык — по прямой просьбе). Название = «что делает» + контекст (если отличает похожие). Описание — 1–2 предложения: что делает, какие сущности затрагивает, результат. Версии/пакеты/идентификаторы — в конец.

## Системные свойства

`name` — только латиница, `snake_case`, lowercase, dot-notation по шаблону `{application}.{module}.{parameter}` (или `…{location}.{attribute}`); суффиксы типов (`_id`/`_ids`) если применимо. `description` — по умолчанию на английском (другой язык — по прямой просьбе); кратко, но достаточно для администратора: для boolean — как меняется поведение при включении/выключении относительно default; для прочих типов — где/зачем используется и формат значения (со сложным форматом — пример).

Примеры: `sdlc.notification.logo_href` → `Specify the image URL to display as logo in the notification header`; `sdlc.time_in_state.years_and_schedule_json` → `Specify a JSON object… Example: { "2025": "Schedule ID" }`. Не: camelCase (`logoHref`), описание в стиле лога.

## Модальные окна

- Заголовок: RU — существительное (`Сохранение нового фильтра`), EN — глагол (`Save a new filter`); EN Title Case, RU Sentence. Это нормальная RU/EN-разница, не ошибка.
- Текст: инструкция/контекст, 1–2 предложения, без техники; точка по общему правилу.
- Кнопки: соответствуют действию модалки; отмена — строго `Назад / Back`; подтверждение — `Сохранить / Save` или по заголовку (`Delete`). Не использовать `OK` вместо явного действия.

## Email-уведомления (`sys_notification_template`)

- **Subject**: суть события + идентификатор записи (номер/имя); ≤~80 символов; Sentence case; без точки; без префикса `Уведомление:`/`Notification:`; переменные `${current.field}`, `${event.param_N}`. Пример: `Согласование отсутствия: ${current.number}` / `Absence approval: ${current.number}`.
- **Заголовок в теле**: дублирует/раскрывает subject; без приветствий.
- **Блоки «ключ—значение»**: жирный label (как заголовок колонки) + `${current.field}`; от важных к вспомогательным; не дублировать данные из заголовка.
- **CTA**: одна основная кнопка; глагол + объект; RU императив / EN base verb; ссылка `${script:getRecordURL}`. Не: `Нажмите здесь`/`Click here`, несколько CTA одного уровня.

## Плюрализация (RU)

Числительное + существительное требует 3 форм. Использовать скрипт-хелпер (`${script:getRuMonthForm}`), не хардкодить одну форму (`${n} месяцев` некорректно при n=1). В спецификации указывать необходимость плюрализации с примерами форм:
```
RU: "Истекает через {n} {день/дня/дней}"
EN: "Expires in {n} {day/days}"
```

| Форма | Числа | Пример |
|---|---|---|
| Им. ед.ч. | 1, 21, 31… | `1 день`, `21 задача` |
| Род. ед.ч. | 2–4, 22–24… | `2 дня`, `23 задачи` |
| Род. мн.ч. | 5–20, 25–30… | `5 дней`, `14 задач` |

## Виджетные строки (SourceMessage / SimpleMessage)

Строки виджетов не привязаны к полям сущностей — механизм `SourceMessage` + `Message`. Не хардкодить текст в HTML: грузить через `SimpleMessage` в серверном скрипте → `data.translations` → `{data.translations.key}`. Ключ `SourceMessage.message` — всегда EN, читаемая фраза Sentence case (`"Your ticket is registered"`, не `"TICKET_REG"`); RU-перевод смысловой (`Ваше обращение принято`, не «Ваш тикет зарегистрирован»). Префикс продукта (`(ITSM) …`) — по конвенции продукта (AGENTS.md).

| Сценарий | Механизм |
|---|---|
| Текст кнопки/заголовка/сообщения в виджете | `SourceMessage` + `Message` через `SimpleMessage` |
| Сообщение в скрипте (`addInfoMessage`/`addErrorMessage`) | `new SimpleMessage().getMessage('key')` |
| Название таблицы/колонки/choice/секции | `SysTranslation` (Translated Text) — **НЕ** SourceMessage |

## Пустые состояния

Объяснить **почему** пусто и **что сделать**. Заголовок — констатация без восклицания; подзаголовок — подсказка действия. Sentence case; без эмодзи; не формулировать как ошибку. Пример: `Задач пока нет` / `No tasks yet` + `Создайте первую задачу, чтобы начать работу` / `Create your first task to get started`. Не: `Ошибка: данные не найдены`, `Нет данных` без подсказки.
