## Назначение

Оркестратор кодогенерации: запускает `code-author` пофазно, затем цикл ревью `code-reviewer` → `code-author`(fix) до чистого результата.

Синтаксис: без аргументов — все фазы; `N` — только фаза N; `N-M` — фазы N–M.

`<product>` — любой продукт, включая `sa/`.

## Шаг 1: Проверка версии

`version` из `.simplegen/state.json` vs `simplegen --version`: CLI ниже — `npm update @simplegen/simplegen`; выше — `/simplegen.init`; совпадают — продолжить.

## Шаг 2: Загрузить контекст

Прочитать активную фичу (`SIMPLEGEN_ACTIVE_FEATURE` в `.env`). Нет `_task_plan.md` → предложить `/simplegen.spec_plan`. Нет `_spec.md` → ошибка.

## Шаг 3: Генерация

Запустить `code-author` в режиме **generate**, передав: путь продукта, `current_feature_path`, аргументы фаз из `$ARGUMENTS`.

Если `code-author` вернул запрос на уточнение (`NEEDS_USER_INPUT`) — передать вопрос пользователю и не продолжать до ответа.

## Шаг 4: Цикл ревью → фикс

Повторять до `VERDICT: PASS`, не более 3 итераций:

1. Запустить `code-reviewer`. `VERDICT: PASS` → выйти из цикла.
2. `VERDICT: FAIL`:
   - Есть `NEEDS_USER_INPUT` → показать вопросы, дождаться ответов.
   - Только `AUTO` → `code-author`(fix) с ISSUES без паузы.
3. Те же ISSUES дважды → остановиться, эскалировать.

После 3 итераций без PASS — показать остаточные ISSUES, спросить пользователя.

## Режим ultra

`--ultra` в аргументах — вызов из `/simplegen.ultra` (канон — `ultra-rules`). Субагентам — `Режим: ultra:auto`. Отличия:

- **Шаг 1** пропустить — версию проверил оркестратор.
- **Синтаксис.**
  - `--ultra N` — только генерация фазы N (Шаг 3), без цикла ревью.
  - `--ultra review N` или `--ultra review N,K,…` — только цикл ревью (Шаг 4) по фазам пачки, номера могут идти не подряд. `code-reviewer` получает номера фаз, их коммиты (`ultra.phases.<N>.commits`) и строку `Готовые фазы: <фазы с code generated / deployed>`. Коммиты фаз пула в истории перемешаны, поэтому ревью идёт по коммитам, а не по диапазону; что проверяется — в разделе «Режим ultra» `code-reviewer`.
  - `--ultra review` — только цикл ревью по всему диффу задачи `initial_commit_sha..HEAD`: стыки фаз.
- **Задание `code-author`** — во всех вызовах, generate и fix, вместе с аргументами передать строки, полученные от оркестратора:
  - номера задач фазы — снимок оркестратора;
  - `Чужая работа: <файлы>`;
  - `Только свои файлы: <файлы>` — если оркестратор её передал (фаза пула).

  `ULTRA_FOREIGN` в отчёте `code-author` (fix) → сделанное закоммитить, цикл ревью прервать и вернуть оркестратору `ULTRA_FOREIGN` с оставшимися ISSUES; во флаги их не писать. После склейки оркестратор вызывает `--ultra review` по фазам исправления и склеенной фазе заново, счёт итераций начинается сначала (правило очерёдности `/simplegen.ultra`).
- **Шаг 3.** Уточнений не бывает: `code-author` в режиме ultra решает сам и возвращает `ULTRA_ASSUMPTIONS`.
- **Шаг 4.**
  - **Узкие ревьюеры.** Вместо одного `code-reviewer` — несколько, одним сообщением, каждому строка `Фокус: <область>` (области и что в них проверяется — `code-reviewer`, «Режим ultra»):
    - `план` — всегда;
    - `скрипты` — в диффе есть `.js`;
    - `данные` — в диффе есть `data-structure/` или `access-control/`;
    - `интерфейс` — в диффе есть виджеты, формы, списки, меню или локализация.

    Итог цикла — объединение: ISSUES всех ревьюеров без повторов (одно место и одно действие — один пункт), `VERDICT: PASS` — только если PASS у всех. `code-author` (fix) получает объединённый список. Следующая итерация — только ревьюеры, у которых был FAIL; финальное ревью (`review` без номеров) — все применимые. Счёт итераций — общий на цикл.
  - `NEEDS_USER_INPUT` не показывать: `code-author` (fix) принимает рекомендуемый вариант (по плану и правилам `simple_types/`) и возвращает `ULTRA_ASSUMPTIONS`.
  - После каждого `code-author` (fix) — коммит, и только затем повторный `code-reviewer`. Ревьюер читает закоммиченный диапазон: без коммита он увидит старый код и сочтёт ISSUES повторившимися. В коммит — только файлы из отчёта `code-author`; `_task_plan.md` — никогда: `[x]` ставит оркестратор. Сообщение:
    - для `review N` — `fix: <task_id> — ревью фазы N, итерация K`;
    - для `review N,K,…` — `fix: <task_id> — ревью фаз <номера>, итерация K`;
    - для `review` — `fix: <task_id> — финальное ревью, итерация K`.
  - Нет PASS после 3 итераций или ISSUES повторились → остаточные ISSUES вернуть как флаги и не спрашивать.
- **Итог.** Вернуть оркестратору:
  - статус фаз;
  - `VERDICT` и число итераций (для `review`);
  - `ULTRA_ASSUMPTIONS`;
  - флаги.
