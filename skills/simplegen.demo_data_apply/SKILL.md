## Назначение

> **⚡ BETA**: Формат `_demo_data.json` может измениться в будущих версиях. Проверяйте данные перед применением.

Команда `/simplegen.demo_data_apply` создаёт на стенде runtime-записи, описанные в `_demo_data.json`
активной фичи: демо-пользователей, их роли, справочники и фоновые записи. Работает через CLI
`simplegen demo apply`.

> **Это единственная команда, которая пишет на стенд не через SOP.** Демоданные — runtime-записи, они
> не входят в конфигурацию, не попадают в DSL и в SOP (`project-core-rule`, раздел «Деплой»).
> Конфигурация по-прежнему меняется только через `/simplegen.product_patch` и `/simplegen.product_build`.

> **Примечание**: `<product>` в этом документе означает любой продукт, включая `sa/` с вендорскими правами.

---

## Синтаксис

```
/simplegen.demo_data_apply            # превью, подтверждение, создание
/simplegen.demo_data_apply --dry-run  # только превью, ничего не создавать
```

## Алгоритм работы

### Шаг 0: Проверить версию simplegen (⚠️ ОБЯЗАТЕЛЬНО)

Сравнить `version` (`.simplegen/state.json`) с выводом `simplegen --version`: CLI ниже — `npm update @simplegen/simplegen`; CLI выше — `/simplegen.init`; совпадают — продолжить. Правило (канон) — `project-core-rule` (always-on).

### Шаг 1: Прочитать контекст

1. Прочитать активную фичу (`SIMPLEGEN_ACTIVE_FEATURE` в `.env`)
2. Проверить наличие `<product>/<current_feature_path>/_demo_data.json`
3. Файла нет — ошибка:
   ```
   ⚠️ Файл `_demo_data.json` не найден.
   → `/simplegen.demo_data_prepare` — сгенерировать демоданные
   ```

### Шаг 2: Превью

Выполнить `simplegen demo apply --dry-run` и показать вывод **как есть**.

Dry-run не создаёт ни одной записи. Имена ролей при этом проверяются по стенду, поэтому
несуществующая роль видна до применения.

Дождаться подтверждения: «Создаю записи на стенде? (да/нет)»

При `--dry-run` в `$ARGUMENTS` — на этом остановиться, вывести план и не спрашивать подтверждения.

### Шаг 3: Создать записи

Выполнить `simplegen demo apply`. Команда создаёт записи в порядке зависимостей, разворачивает
`$alias` в `sys_id` и записывает их обратно в `_demo_data.json`. Записи с уже заполненным `sys_id`
пропускаются — повторный запуск не создаёт дублей.

| Исход | Что делать |
| ----- | ---------- |
| Все записи созданы | перейти к выводу, напомнить про `manual_steps` |
| Часть записей `failed` | показать строки `failed` как есть; разбор причин — `demo-rules`, раздел «Демоданные» |
| `ACL restrictions` на `sys_user_has_role` | подсказать `SIMPLEONE_ELEVATED_ROLES=security_admin` в `.env` и повторный запуск: созданное не продублируется |
| Обязательное поле не заполнено | назвать колонку и файл экспорта, где смотреть (`platform/data-structure/columns/<table>.ts`), предложить поправить `_demo_data.json` |
| Пользователь ответил «нет» | остановиться: файл на месте, применить можно позже |

Ручные шаги из `manual_steps` команда не выполняет — печатает списком.

### Режим ultra

`/simplegen.ultra` эту команду больше не вызывает: демоданные прогона — только файл в MR, тесты изолированы от них. Раздел ниже — для ручного вызова с `--ultra`.

`--ultra` в аргументах — вызов из `/simplegen.ultra` (канон — `ultra-rules`). Согласие на демоданные получено на интервью. Отличия:

- **Шаг 0** пропустить — версию проверил оркестратор.
- **Шаг 2.** Dry-run выполнить, вывод вернуть оркестратору для журнала; подтверждения не ждать.
- **Тестовые данные.** Записи `[TEST <task_id>]` и данные для воспроизведения на стенде демоданными не считаются: применять весь `_demo_data.json`, не сопоставляя с ними записи и не пропуская их.
- **Шаг 3.** `failed` и ACL-ошибки не исправлять. Кейсы под пользователями, которые не создались, `test-author` пометит SKIP.
- **Итог.** Журнал не писать — вернуть оркестратору, он перенесёт во флаги:
  - сколько записей создано;
  - строки `failed` (таблица, alias, ошибка) и ACL-ошибки;
  - список `manual_steps`;
  - созданных демо-пользователей: логин и роли.

## Формат вывода

### Записи созданы

```markdown
# ✅ Демоданные применены

**Файл**: `<current_feature_path>/_demo_data.json`
**Стенд**: $SIMPLEONE_URL

| Результат  | Количество |
| ---------- | ---------- |
| Создано    | N          |
| Пропущено  | M (уже были созданы) |
| Не создано | 0          |

## Созданные записи

| #   | Таблица           | Alias             | sys_id             |
| --- | ----------------- | ----------------- | ------------------ |
| 1   | employee          | user_manager      | 166189441111831205 |
| 2   | sys_user_has_role | user_manager_role | 166189441111831287 |

## Ручные шаги (выполнить самостоятельно)

| #   | Описание               | Где                            |
| --- | ---------------------- | ------------------------------ |
| 1   | Загрузить SOP на стенд | /record/sys_vcs_retrieved_pack |

## Следующий шаг

→ `/simplegen.demo_run` — прогнать демонстрацию
```

### Часть записей не создана

```markdown
# ⚠️ Демоданные применены частично

**Файл**: `<current_feature_path>/_demo_data.json`

| Результат  | Количество |
| ---------- | ---------- |
| Создано    | 3          |
| Пропущено  | 0          |
| Не создано | 2          |

## Не создано

| Alias             | Таблица           | Причина                                     |
| ----------------- | ----------------- | ------------------------------------------- |
| user_manager_role | sys_user_has_role | ACL restrictions — нужна elevated-роль      |
| task_agreed       | task              | зависит от невыполненной записи user_manager_role |

## Как исправить

- `SIMPLEONE_ELEVATED_ROLES=security_admin` в `.env`, затем повторить команду
- Созданные записи не продублируются — у них уже заполнен `sys_id`
```

## Особые случаи

### Нет активной фичи

```markdown
⚠️ Активная фича не установлена.

→ `/simplegen.context_set <task_id>`
```

### Файл пустой (только ручные шаги)

```markdown
ℹ️ В `_demo_data.json` нет автоматизируемых записей — только `manual_steps`.

| #   | Описание               | Где                            |
| --- | ---------------------- | ------------------------------ |
| 1   | Загрузить SOP на стенд | /record/sys_vcs_retrieved_pack |

Выполните шаги вручную, затем → `/simplegen.demo_run`
```

### Файл невалиден

CLI сам проверяет структуру и печатает все проблемы списком (неизвестный `$alias`, дубль alias,
цикл в `depends_on`). Показать вывод как есть и предложить поправить `_demo_data.json` или
пересоздать его через `/simplegen.demo_data_prepare`.

## Загрузка контекста

Перед работой обязательно:
1. **`demo-rules`** — канон демоданных (какие поля брать из экспорта, elevated-роли, чем демоданные отличаются от демонстрации)
2. **`_demo_data.json`** — полностью
3. **`.env`** — `SIMPLEONE_URL`, `SIMPLEGEN_ACTIVE_FEATURE`
