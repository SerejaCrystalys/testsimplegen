## Назначение

Оркестратор генерации диаграмм: запускает субагента `diagram-author`, который по исходному markdown-файлу строит диаграммы PlantUML и складывает их **рядом с исходником** в `<имя файла>_diagrams.md` + `.puml`/`.svg`.

Артефакты команды — **для человека**: проверить статусную модель и связи глазами, обсудить сценарии с командой, спроектировать пользовательский flow. Остальные субагенты SimpleGen их не читают, а исходные файлы остаются текстовыми — так обязательный контекст агентов отделён от контекста по требованию для человека.

## Синтаксис

```
/simplegen.diagrams_build tasks/<task_id>/_spec.md      # диаграммы к спецификации
/simplegen.diagrams_build tasks/<task_id>/_task_plan.md # диаграммы к плану
/simplegen.diagrams_build docs/<slug>.md                # диаграммы к документации модуля
/simplegen.diagrams_build                               # _spec.md активной задачи
/simplegen.diagrams_build <путь> модель статусов        # только запрошенная диаграмма
```

Без аргумента берётся `_spec.md` активной фичи (`SIMPLEGEN_ACTIVE_FEATURE` в `.env`); активной задачи нет — сообщить и попросить путь. Всё, что указано после пути, — пожелание по типу или теме диаграммы: тогда строится только запрошенное.

В исходный файл команда добавляет **только раздел «Диаграммы» со ссылками** на `.svg` и `.puml`; картинки и PlantUML-код в него не встраиваются. Повторный запуск заменяет этот раздел целиком, остальной текст не трогает.

## Шаг 1: Проверка версии

`version` из `.simplegen/state.json` vs `simplegen --version`: CLI ниже — `⚠️ обновите: npm update @simplegen/simplegen`; CLI выше — `⚠️ выполните /simplegen.init`; совпадают — продолжить.

## Шаг 2: Генерация

Запусти субагента `diagram-author`, передав путь исходного файла и путь продукта. Субагент определяет, какие диаграммы нужны, пишет `.puml`, пытается отрендерить `.svg`, собирает `<имя>_diagrams.md` и вписывает раздел «Диаграммы» со ссылками в исходный файл.

Если субагент вернул запрос на уточнение (файл не найден, в исходнике нет данных для диаграмм, неоднозначность) — передать вопрос пользователю и не продолжать до ответа.

## Шаг 3: Итог

Вывести отчёт `diagram-author`: какие диаграммы построены, где лежат, отрендерены ли `.svg`.

Если рендерер PlantUML не найден — показать инструкцию из отчёта (`.puml` при этом уже готовы, диаграммы открываются расширением PlantUML в VS Code). Отсутствие рендерера — не ошибка команды.

⚠️ Файл `_diagrams.md` **пересобирается целиком** при каждом запуске: правки вносите в исходный `_spec.md` / `_task_plan.md` / `docs/<slug>.md` и перегенерируйте.

## Режим ultra

`--ultra` первым словом аргументов, затем путь исходника (`--ultra tasks/<task_id>/_spec.md`) — вызов из `/simplegen.ultra` (канон — `ultra-rules`). `diagram-author` получает `Режим: ultra:auto`, путь исходника, путь продукта и — для `_spec.md` при `ultra.spec_owner = analyst` — строку «спека аналитика»: тогда раздел «Диаграммы» в спеку не пишется. Отличия:

- **Шаг 1** пропустить — версию проверил оркестратор.
- **Шаг 2.** Вопросов нет: `diagram-author` решает по своему разделу «Режим ultra». `ULTRA_BLOCKED` → вернуть оркестратору, диаграммы пропускаются с флагом.
- **Шаг 3.** Отсутствие рендерера — не флаг: `.puml` в MR достаточно. Вернуть оркестратору:
  - построенные диаграммы;
  - список созданных и удалённых файлов;
  - пункты «Замечено в исходнике» — они идут во флаги журнала, а по готовой спеке — в «Замечания к спецификации».
