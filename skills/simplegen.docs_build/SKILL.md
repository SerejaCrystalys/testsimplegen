## Назначение

Оркестратор обновления **технической документации модулей**: запускает субагента `docs-author`, который инкрементально пополняет `<product>/docs/<slug>.md` структурными данными из `_spec.md` задачи (таблицы, колонки, доступы) и ведёт Changelog.

Это внутренняя документация разработчиков — **не** публичная пользовательская документация, **не** функциональные описания. Задача всегда в рамках **одного** продукта; `platform/` не документируется (`sa/` при вендорских правах — это тоже продукт). Папка `docs/` **не** участвует в SOP build.

> **Когда запускать**: после финализации спецификации задачи, когда модель данных стабильна (оптимально — перед генерацией кода).

## Синтаксис

```
/simplegen.docs_build tasks/<task_id>
```

> **⚠️ Обязательно указать задачу.** Полная генерация «с нуля» не поддерживается — документация пополняется инкрементально из спеки конкретной задачи.

## Шаг 1: Проверка версии

`version` из `.simplegen/state.json` vs `simplegen --version`: CLI ниже — `⚠️ обновите: npm update @simplegen/simplegen`; CLI выше — `⚠️ выполните /simplegen.init`; совпадают — продолжить.

## Шаг 2: Запустить генерацию

Запусти субагента `docs-author`, передав `$ARGUMENTS` (путь задачи `tasks/<task_id>`). Субагент определяет продукт задачи (`platform/` НЕ документируется), целевой модуль, извлекает структуру из `_spec.md`, консервативно мержит `docs/<slug>.md`, ведёт Changelog и обновляет `docs/index.md`.

Если `docs-author` вернул запрос на уточнение (модуль не определён, конфликт доступов, нет секции «Модули продукта», повреждённая структура файла) — передать вопрос пользователю и не продолжать до ответа.

## Шаг 3: Итог

Вывести отчёт `docs-author` (затронутые модули, выжимка из спеки).

⚠️ **ОБЯЗАТЕЛЬНО**: провести ревью сгенерированной документации перед коммитом — корректность привязки к модулю, полнота выжимки, отсутствие ошибок. При необходимости дополнить вручную и закоммитить.

## Режим ultra

`--ultra` первым словом аргументов, затем путь задачи (`--ultra tasks/<task_id>`) — вызов из `/simplegen.ultra` (канон — `ultra-rules`). `docs-author` получает `Режим: ultra:auto`, путь задачи и путь продукта. Модуль задан полем `module` в `simplegen.json` по ответу интервью. Отличия:

- **Шаг 1** пропустить — версию проверил оркестратор.
- **Шаг 2.** Вопросов нет: `docs-author` решает по своему разделу «Режим ultra». `ULTRA_BLOCKED` → вернуть оркестратору, слой документации пропускается с флагом.
- **Шаг 3.** Ревью человеком переносится в чек-лист ревьюера MR. Коммит делает оркестратор. Вернуть оркестратору:
  - затронутые модули;
  - `ULTRA_ASSUMPTIONS`;
  - `ULTRA_BLOCKED`.
