## Назначение

Команда `/simplegen.product_rollback` откатывает на стенде одну сопку (local pack) активной задачи через CLI `simplegen rollback`: изменения, записанные в сопку, снимаются со стенда. SOP-файлы и код в репозитории не меняются.

---

## Алгоритм работы

### Шаг 0: Проверить версию simplegen (⚠️ ОБЯЗАТЕЛЬНО)

Сравнить `version` (`.simplegen/state.json`) с выводом `simplegen --version`: CLI ниже — `npm update @simplegen/simplegen`; CLI выше — `/simplegen.init`; совпадают — продолжить. Правило (канон) — `project-core-rule` (always-on).

### Шаг 1: Прочитать контекст

1. Прочитать активную фичу (`SIMPLEGEN_ACTIVE_FEATURE` в `.env`, формат `<product>/<task_id>`): `<productName>` и `<current_feature_path>`.
2. Определить `localPackId`. Взять первый найденный вариант:
   1. 18-значный ID в `$ARGUMENTS`.
   2. `last_patch.local_pack_id` из `<product>/<current_feature_path>/simplegen.json`. Это сопка задачи, с которой работает CLI: в неё дописывает `patch`, её создаёт импорт `build`. Пустая строка означает, что сопки нет: последнему `build` нечего было собирать, или он не определил сопку импорта.
   3. Только в крайнем случае — самый свежий (по `build.createdAt`) ненулевой `build.localPackId` из `<product>/<current_feature_path>/build_logs/*.log.json`. Подходят логи сборок и `…_patch.log.json`. `…_export.log.json` и `…_rollback.log.json` не брать: сопку из лога выгрузки `build` откатывает сам. Пропустить ID, который уже откачен: есть `…_rollback.log.json` с этим `build.localPackId` и с `build.rolledBack: true` или `build.state: "rollbacked"`. `build_logs/` в `.gitignore`, поэтому на другой машине логов нет.

### Шаг 2: Проверить возможность отката

- `localPackId` не найден ни одним способом → «Нечего откатывать».

### Шаг 3: Выполнить откат

Выполни в терминале: `simplegen rollback <productName> <localPackId>`.

### Шаг 4: Результат

Исход определяется **наличием JSON в stdout**: `{ productName, localPackId, state, rolledBack, contained, logPath }`.

| Исход | Как распознать | Что сообщить |
| ----- | -------------- | ------------ |
| Откат выполнен | JSON, `rolledBack: true` | `state` — состояние сопки до отката. `contained` — что в ней было: `insert`/`update`/`delete`/`total` (`null` — стенд не ответил) |
| Откат не потребовался | JSON, `rolledBack: false` | Ничего не откатывалось: сопка уже откачена (`state: "rollbacked"`) или пуста (`"empty"`). Это не ошибка |
| Откат не выполнен | JSON нет, в stderr `[error] …` | Сообщение и действие из списка «Ошибки деплоя, которые не исправить правкой DSL» (`project-core-rule`), если оно там есть |

Лог CLI пишет сам при любом исходе, ничего сохранять не нужно. Путь берётся из `logPath` (`null`, если лог не записался). При ошибке — самый свежий `build_logs/[<PRODUCT>]_<task_id>_<YYYY-MM-DD>_<HH-MM-SS>_rollback.log.json`; если CLI упал до обращения к стенду, лога нет.

`simplegen.json` откат не меняет. Записи сопки со стенда сняты, а `/simplegen.product_patch` отправляет только изменения после `last_patch.commit_sha`: откаченные записи он не вернёт, только откроет новую сопку. Вернуть на стенд всю задачу — `/simplegen.product_build`, он собирает её целиком от `initial_commit_sha`. Сказать об этом пользователю.

## Формат вывода

### Успешный откат

```markdown
# ✅ Откат выполнен

## Результат

| Параметр            | Значение                                                            |
| ------------------- | ------------------------------------------------------------------- |
| Сопка               | `123456789012345678`                                                |
| Состояние до отката | `in-progress`                                                       |
| Было в сопке        | 12 записей: 9 insert, 3 update, 0 delete                            |
| Лог отката          | `build_logs/[ITSM]_STR001234_2025-12-10_14-30-05_rollback.log.json` |

## Следующий шаг

→ Исправьте проблему в коде
→ `/simplegen.product_build` — вернуть на стенд всю задачу (откаченные записи `/simplegen.product_patch` не вернёт)
→ `/simplegen.product_patch` — отправить только новые правки
```

### Откат не потребовался

```markdown
# ✅ Откат не потребовался

Сопка `123456789012345678` уже в состоянии `rollbacked` (или `empty` — пуста): CLI ничего не менял.

Лог: `build_logs/[ITSM]_STR001234_2025-12-10_14-30-05_rollback.log.json`
```

### Нечего откатывать

```markdown
⚠️ Откатывать не на что.

ID сопки не передан, в `simplegen.json` задачи нет `last_patch.local_pack_id`, в `build_logs/` нет неоткаченных сопок. Это может означать:
- Деплой ещё не выполнялся
- Последней сборке нечего было собирать
- Логи были удалены или деплой шёл с другой машины

## Альтернативы

→ `git reset` — откатить код
→ `/simplegen.code_generate` — перегенерировать
→ `/simplegen.product_patch` — новый деплой
```

### Ошибка отката

```markdown
# ❌ Откат не выполнен

## Ошибка

```
[текст `[error] …`]
```

## Что сделать

[действие из списка `project-core-rule`, если сообщение там есть]

## Лог

`build_logs/[ITSM]_STR001234_2025-12-10_14-30-05_rollback.log.json` (если CLI упал до обращения к стенду, лога нет)

## Следующий шаг

→ Проверьте логи на стенде
→ Обратитесь к администратору
```

## Известные ограничения отката

1. **Дубликаты виджетов**: Откат сопки не удаляет записи, созданные неудачным билдом. Дубликаты виджетов (`sys_widget`, `sys_widget_instance`) могут остаться на инстансе. После отката — проверить и удалить вручную через интерфейс.
2. **Версия npm-пакета**: Роллбэк НЕ должен менять версию npm-пакета в `package.json`. Если после отката `package.json` изменился — восстановить оригинальную версию вручную.

## Особые случаи

### Нет активной фичи

```markdown
⚠️ Активная фича не установлена.

→ `/simplegen.context_set <task_id>`
```

### Глубокий откат

```markdown
ℹ️ Чтобы откатить другую, более раннюю сопку задачи:

1. Найдите её ID в поле `build.localPackId` логов `build_logs/*.log.json`
2. Запустите `/simplegen.product_rollback <localPackId>`
```

- ID откаченной сопки и что в ней было (`contained`)
