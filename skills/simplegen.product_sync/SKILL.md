## Назначение

Команда `/simplegen.product_sync` синхронизирует локальные `platform/`, `sa/` и `<product>/domain/` с текущей конфигурацией на стенде SimpleOne.

> **Примечание**: `<product>` в этом документе означает любой продукт, включая `sa/` с вендорскими правами. Для SA синхронизируется `sa/domain/`.

### Режим синхронизации по пакету

Если вместо названия продукта передать **18-значный числовой ID локального пакета** (local pack ID), синхронизация выполнится **только для записей, входящих в этот пакет**.

- Обновляются (или удаляются) только те файлы в `domain/`, которые затронуты записями пакета.
- `platform/` и `sa/` **не перезатираются**.
- Продукт определяется автоматически по приложению пакета.

Это полезно, когда нужно быстро подтянуть изменения конкретного пакета без полной пересинхронизации.

| Каталог/файл               | Статус         |

| `.claude/`, `.opencode/`   | ❌ Не трогается |

## Алгоритм работы

### Шаг 1: Определить продукт

1. Если пользователь указал продукт или ID пакета — использовать его
2. Если не указал — определить по каталогу продукта. Каталог продукта — это slug в нижнем регистре (`itsm/`, `service-desk/`), а CLI нужно точное имя приложения (`productName`): бери его из третьей строки `<product>/AGENTS.md` (`` `<product>/` — продукт **<Имя>**. ``)
3. Для `sa/` имя не нужно: выполни `simplegen sync` без аргумента — `platform/` и `sa/` выгружаются всегда

### Шаг 1.5: Проверить версию simplegen (⚠️ ОБЯЗАТЕЛЬНО)

Сравнить `version` (`.simplegen/state.json`) с выводом `simplegen --version`: CLI ниже — `npm update @simplegen/simplegen`; CLI выше — `/simplegen.init`; совпадают — продолжить. Правило (канон) — `project-core-rule` (always-on).

### Шаг 2: Выполнить синхронизацию

Выполни в терминале: `simplegen sync <productName>` или `simplegen sync <localPackId>`

- Если аргумент — 18-значное число, CLI интерпретирует его как **local pack ID** и выполняет точечную синхронизацию (см. «Режим синхронизации по пакету» выше).
- Иначе аргумент рассматривается как **название продукта**, и выполняется полная синхронизация. Имя должно в точности (с учётом регистра) совпадать с `name` приложения на стенде. Если CLI ответил `No application "…" on the instance`, возьми правильное имя из подсказки (`did you mean`) или из списка приложений в ошибке и повтори команду.

CLI автоматически:
- Подключится к стенду SimpleOne
- Полностью перезатрёт `platform/`
- Полностью перезатрёт `sa/`
- Полностью перезатрёт `<product>/domain/`

## Особые случаи

### Нет подключения

```markdown
# ❌ Не удалось подключиться к стенду

## Ошибка

```
Connection refused: https://dev.example.com
```

## Проверьте

- Доступность стенда
- Настройки подключения
- Авторизационные данные

→ После устранения проблемы повторите `/simplegen.product_sync`
```

### Локальные изменения

```markdown
⚠️ В `domain/` есть незакоммиченные изменения.

Синхронизация **перезатрёт** эти изменения.

| Файл                      | Статус   |
| ------------------------- | -------- |
| domain/business-logic/... | Modified |
| domain/data-structure/... | Modified |

Варианты:
A) Закоммитить изменения и повторить
B) Принудительно синхронизировать (потерять изменения)

→ `git stash` — сохранить изменения
→ `/simplegen.product_sync --force` — принудительно
```

## Флаги

| Флаг              | Описание                                                     |
| ----------------- | ------------------------------------------------------------ |
| `--force`         | Принудительная синхронизация, игнорирует локальные изменения |
| `--platform-only` | Обновить только platform/                                    |
| `--sa-only`       | Обновить только sa/                                          |
| `--domain-only`   | Обновить только domain/                                      |
