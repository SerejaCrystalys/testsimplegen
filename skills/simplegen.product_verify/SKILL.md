## Назначение

Команда `/simplegen.product_verify` запускает CLI `simplegen verify` и показывает, сойдётся ли проверка пакетов в merge request: всё ли, что описано в DSL, попало в `.sop`, нет ли в пакете лишнего и соблюдены ли правила для записей.

Проверка оффлайн: к стенду не обращается и ничего не меняет — ни DSL, ни `.sop`, ни стенд. Исправления команда только предлагает.

Проверяется **закоммиченное** состояние — ровно то, что увидит merge request.

## Шаг 1: Проверка версии

`version` из `.simplegen/state.json` vs `simplegen --version`: CLI ниже — `npm update @simplegen/simplegen`; выше — `/simplegen.init`; совпадают — продолжить. Правило (канон) — `project-core-rule` (always-on).

## Шаг 2: Что проверять

| Ввод пользователя | Команда |
| ----------------- | ------- |
| пусто | `simplegen verify` — все задачи, чей `.sop` менялся в ветке, как в merge request |
| задача (`STR001234`) | `simplegen verify <product> <task_id>` — продукт из `SIMPLEGEN_ACTIVE_FEATURE` в `.env` |
| продукт и задача (`sa STR001234`) | `simplegen verify <product> <task_id>` |
| названия проверок | добавить `--check <список через запятую>`: `compare-dsl`, `containers`, `cyrillic`, `translations`, `application`, `policy` |

Незакоммиченные изменения в DSL или `.sop` → предупредить: они в проверку не попадут, и merge request их тоже не увидит. Предложить закоммитить и спросить, проверять ли без них.

## Шаг 3: Проверка

Выполнить команду и показать отчёт **как есть** — он уже написан для человека: по каждой задаче вердикт, у каждого расхождения — что не так, что сделать и полный список записей.

Код возврата `0` — всё сходится, `1` — есть расхождения или задачу не удалось проверить. «Итог: проверять нечего» — это не успех: ни одна задача не проверена.

## Шаг 4: Что предложить дальше

Под отчётом свести расхождения к действиям. Ничего не запускать без подтверждения пользователя.

| В отчёте | Предложить |
| -------- | ---------- |
| `В пакете нет N записей из DSL`, `В составе формы, списка или воркфлоу нет …` | `/simplegen.product_build`, закоммитить `.sop` |
| `В пакете N лишних записей`, `В составе формы, списка или воркфлоу … лишн…` | запись нужна — `/simplegen.product_sync` и закоммитить DSL, не нужна — убрать её из `.sop` и закоммитить |
| `Кириллица в машинных полях` | перенести текст в переводы, затем `/simplegen.product_build` |
| `Переводов без полного набора языков` | добавить недостающие языки, затем `/simplegen.product_build` |
| `… из чужого приложения` | исправить `application_id` в `.sop` и закоммитить |
| `Записей без record_policy = Protected` | исправить `record_policy` в `.sop` и закоммитить |
| `Задачу не удалось проверить` | то, что написано в строке «Сделать» под ошибкой |
| `Итог: проверять нечего` | `/simplegen.product_build`, закоммитить `.sop` |
| `Unknown command: verify` | `npm update @simplegen/simplegen` |

## Режим ultra

`--ultra` в аргументах — вызов из `/simplegen.ultra` (канон — `ultra-rules`). Отличия:

- **Шаг 1** пропустить — версию проверил оркестратор.
- **Шаг 2.**
  - Команда — `simplegen verify <product> <task_id>` для активной задачи. Без `--json`: в нём нет строки «Итог» и текстов расхождений, по которым выбирается действие.
  - Незакоммиченные изменения не обсуждать: оркестратор коммитит до вызова. Грязные `<product>/domain/` или `.sop` → вернуть ошибку оркестратору. Остальные файлы задачи (`_demo_data.json`, `_demo_plan.md`, `_local/_mr.md`) может писать параллельный фон: `verify` их не читает, это не ошибка.
- **Шаг 3.** Исход — по коду возврата и строке «Итог». «Итог: проверять нечего» — провал, хотя код возврата `0`.
- **Шаг 4.** Подтверждения не ждать. Вернуть оркестратору:
  - исход;
  - строку «Итог»;
  - расхождения с действиями из таблицы.

  Действия выполняет оркестратор — не более 3 попыток, затем стоп. Исключение: действия, которые правят `.sop` руками или требуют `/simplegen.product_sync`, в режиме ultra не выполняются — это сразу стоп с описанием расхождения.

## Формат вывода

### Всё сходится

```markdown
# ✅ Пакеты сходятся с DSL

[отчёт simplegen verify]

## Следующий шаг

→ Пушить и создавать merge request — проверка в пайплайне сойдётся так же
```

### Проверять нечего

```markdown
# ⚠️ Проверять нечего

[отчёт simplegen verify]

Ни у одной задачи в ветке не менялся `.sop` — проверка ничего не сравнила.

## Следующий шаг

→ `/simplegen.product_build` и закоммитить `.sop`, затем повторить `/simplegen.product_verify`
```

### Есть расхождения

```markdown
# ❌ Пакеты не сходятся с DSL

[отчёт simplegen verify]

## Что сделать

| Задача | Расхождение | Действие |
|--------|-------------|----------|
| `sa/tasks/STR001234` | В пакете нет 3 записей из DSL | `/simplegen.product_build`, закоммитить `.sop` |

## Следующий шаг

→ Исправить, закоммитить и повторить `/simplegen.product_verify`
```
