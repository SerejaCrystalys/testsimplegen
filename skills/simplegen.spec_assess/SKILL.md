## Назначение

Проверка критериев приёмки **до** того, как задача пошла в работу: понятны ли они человеку, однозначны ли для реализации, не спрятано ли в одной карточке несколько задач, не конфликтуют ли требования с текущей конфигурацией стенда.

Команда **опциональная** и **ничего не создаёт**: ни каталога задачи, ни файлов, ни записей. Весь разбор уходит в чат — аналитик идёт с ним к тимлиду или владельцу продукта. Критериев нет или они заведомо черновые — команду можно не запускать.

Вердикт носит рекомендательный характер: ничего не блокирует, потому что на этом шаге ещё нечего блокировать.

`<product>` — любой продукт, включая `sa/`. Определяется по каталогу верхнего уровня с `simplegen.json` (один продукт — авто; несколько — по `AGENTS.md` или спросить).

## Синтаксис

```
/simplegen.spec_assess
<критерии приёмки; по желанию — бизнес-описание и ID задачи>
```

Критериев во входных данных нет → спросить один раз и, не получив их, остановиться: оценивать нечего.

## Шаг 1: Проверка версии

1. `version` из `.simplegen/state.json` vs `simplegen --version`.
2. CLI ниже — `⚠️ обновите: npm update @simplegen/simplegen`; CLI выше — `⚠️ выполните /simplegen.init`; совпадают — продолжить.

## Шаг 2: Оценка

Запусти субагента `criteria-assessor`, передав критерии, бизнес-описание (если есть) и путь продукта. Показать его разбор целиком.

## Шаг 3: Итог

К разбору добавить рекомендацию по вердикту:

| Вердикт | Рекомендация |
| ------- | ------------ |
| `PASS` | Критерии готовы — можно в `/simplegen.spec_create` |
| `WARN` | Показать замечания; уточнить формулировки с постановщиком или идти в `spec_create` как есть — решает аналитик |
| `DECOMPOSE` | Показать предлагаемое разделение и вопросы постановщику; обсудить декомпозицию до создания задачи |

Исправленные критерии можно прогнать повторно — команда не хранит состояние.
